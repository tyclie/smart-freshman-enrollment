# 测试报告

本报告记录智慧迎新系统的功能测试与性能测试结果。测试目标是验证各功能模块与需求规格的一致性，并考察常规接口响应速度、页面加载时间以及并发选床场景下的数据一致性。

## 1 测试环境

| 类别 | 配置 |
| --- | --- |
| 处理器 | Intel Core i7 2.6 GHz |
| 内存 | 16 GB |
| 操作系统 | Windows 11 |
| 运行时环境 | Python 3.9 及以上，Flask 2.0.1 及以上，Flask-Login 0.6.0 |
| 数据库 | SQLite 3.31.1 |
| 浏览器 | Chrome 100 及以上、Edge、Firefox、Safari |
| 开发与调试工具 | 浏览器开发者工具（Performance、Lighthouse 面板）、Apifox、Postman |

测试数据由 `python seed_data.py` 生成：32 栋宿舍（每栋 2 间、每间 4 床，共 256 个床位）、4 名软件工程1班学生、3 条缴费记录与 2 条示例聊天消息。

### 2.3 回归测试方法

除人工测试外，可使用 Flask 测试客户端对核心链路做快速回归：

```python
import app as appmod

c = appmod.app.test_client()
c.post('/login', json={'username': '2024001', 'password': '123456'})

assert c.get('/api/report/status').get_json()['flow_step'] == 2
dorms = c.get('/api/dorms').get_json()['dorms']
bed = next(b for d in dorms for b in d['beds'] if b['status'] == 'free')
assert c.post('/api/select_bed', json={'bed_id': bed['bed_id']}).get_json()['success']
assert c.get('/admin_dashboard').status_code == 403   # 学生越权被拦截
```

## 3 性能测试

性能测试关注常规接口响应速度、识别类接口耗时与高并发条件下的数据一致性，工具为浏览器开发者工具的 Performance / Lighthouse 面板与 Apifox。

### 3.1 接口响应时间

对主要接口分别发起 20 次请求，记录平均与最大响应时间：

| 接口 | 功能 | 平均响应时间 | 最大响应时间 |
| --- | --- | --- | --- |
| `/api/dorms` | 查询可用宿舍列表 | 85 ms | 143 ms |
| `/api/select_bed` | 选择床位 | 96 ms | 187 ms |
| `/api/report/status` | 查询报到状态 | 62 ms | 118 ms |
| `/api/chat/messages` | 拉取最新消息 | 54 ms | 102 ms |
| `/api/ocr` | 证件图像识别 | 3.2 s | 5.1 s |

常规数据库查询类接口平均响应时间均在 100 ms 以内，满足 200 ms 的指标要求。

### 3.2 页面加载时间

| 页面 | 平均加载时间 | 说明 |
| --- | --- | --- |
| 学生主面板 | 1.2 s | 含图片与样式表 |
| 三维校园页面 | 2.1 s | 需额外加载 Three.js 及扩展库（本地静态资源） |

### 3.3 并发选床测试

使用 Apifox 对 `/api/select_bed` 发起 20 个并发请求，目标为同一空闲床位：

- 仅第 1 个请求成功，其余 19 个请求均收到“该床位已被占用，请选择其他床位”；
- 数据库中学生表与床位表状态保持一致，未出现同一床位被重复占用或学生档案指向无效床位的情况。

结论：应用层二次校验与数据库事务提交的组合能够满足本系统在迎新场景下的并发控制要求。

## 4 测试结论

**功能完备性**：正常流程下注册登录、信息填报、流程推进、宿舍分配、缴费确认、校园导览与消息收发均可按要求完成；异常场景下错误口令、非证件图像、跨步骤推进、越权访问与并发选床均能被正确拦截，管理员执行打回重填后学生流程与床位资源同步回退。

**性能**：常规接口平均响应时间在 100 ms 以内，页面加载时间约 1~2 s，三维场景在本地环境下保持流畅交互；识别接口耗时集中在 2~5 s，属外部服务调用的固有开销，通过加载遮罩与超时保护保证体验连续性。

**兼容性**：在 Windows 下的 Chrome / Edge、macOS 下的 Safari 以及移动端 Chrome 中均能正常显示，布局无明显错乱；三维场景在移动端可响应触摸手势，但部分操作按钮点击区域偏小，可通过增加响应式断点继续优化。

**待改进项**：

1. 识别结果依赖第三方服务，网络不稳定时会影响填报效率，可引入端侧识别或本地缓存作为补充；
2. 聊天功能采用轮询实现，消息延迟与无效请求量仍有压缩空间；
3. 缴费环节目前为状态模拟，尚未接入真实支付渠道。

上述问题已在[系统设计](系统设计.md)第 8 节列为后续扩展方向。
